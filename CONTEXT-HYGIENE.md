# Context Hygiene

Правила экономии контекста для Claude Code. Скопируй раздел ниже в свой
`CLAUDE.md` (глобальный `~/.claude/CLAUDE.md` или проектный) -- агент будет
соблюдать их сам.

Почему это работает: каждый вызов инструмента -- отдельный запрос, и в каждом
запросе заново оплачивается весь накопленный контекст. Стоимость сессии --
не сумма написанного, а произведение: размер контекста × число вызовов.
Замер на 24 680 ответах модели: 97% объёма токенов и 65% стоимости --
это cache_read, то есть перечитывание уже накопленного.

## Context Hygiene

Цена токена = он оплачивается заново на КАЖДОМ следующем вызове (cache_read).
В длинной сессии это 100+ повторов. 65% стоимости сессии -- перечитывание уже
накопленного контекста. Файл на 3k токенов, прочитанный на 5-м вызове из 120,
стоит ~345k токенов, а не 3k.

- **Читать точечно.** `grep`, `sed -n 'A,Bp'`, `head`. `cat` целиком -- только
  когда файл реально нужен весь.
- **Edit вместо Write** для существующих файлов: Write отправляет всё
  содержимое файла заново на каждом вызове.
- **Резать вывод выборочно.** `| tail -N`, `--quiet`, `grep` вместо `cat` для
  логов, билдов, тестов, установок. НЕ резать диффы и данные, которые надо
  анализировать: перезапуск из-за срезанного нужного куска дороже большого
  вывода.
- **Картинки -- через субагента.** PNG 1920×1080 = 2764 токена, и после Read он
  перечитывается каждый следующий ход. Субагент читает картинку в своём
  контексте и возвращает текстовый вердикт. Если Read всё же в основном
  контексте -- сначала даунскейл: `sips -Z 1024 in.png --out /tmp/small.png`.
- **Никогда не читать пару «эталон + результат» подряд** в основном контексте --
  это удвоение на каждой итерации цикла.
- **Скрипты длиннее ~20 строк -- в файл**, не heredoc в аргументе Bash.
  Инлайн-скрипт платится дважды: как output и потом как cache_read на каждом
  вызове. `Write /tmp/x.py` → `python3 /tmp/x.py`, правки через `Edit`.
- **Обширный поиск -- отдельному агенту** с ограниченным вопросом. Назад --
  пути, факты, открытые вопросы. Не полные дампы файлов в основной чат.
- **Батчить независимые вызовы** в одно сообщение. Зависимые -- по очереди,
  не выдумывать параллелизм там, где его нет.
- **Не перечитывать без причины.** Использовать уже полученные результаты;
  повторное чтение нужно, только если файл изменился или вывод был неполным.
- **Планы держать короткими:** план из ExitPlanMode остаётся в кэше до конца
  сессии и оплачивается на каждом вызове.
- **Одна законченная задача -- одна сессия.** Самый дешёвый `/compact` --
  это новый чат.
- **Модель по фазам:** планирование и архитектура на Opus, рутинный код-ген на
  Sonnet. Разница по ставке ~5x.

## Если меришь токены сам

Claude Code пишет по строке JSONL на каждый блок контента (thinking / text /
tool_use), и каждая строка повторяет `usage` всего ответа целиком. Наивный
построчный подсчёт завышает в ~1.85 раза.

Дедуплицировать надо по `message.id` в пределах файла сессии. Поля кэша
повторяются дословно, но `output_tokens` -- потоковый счётчик, который растёт
от строки к строке: полное значение только на последней. Схлопывать по
максимуму, а не по первому значению.

Реализация: [`parser.py`](src/claude_code_token_meter/parser.py)
